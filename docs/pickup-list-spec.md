# ピックアップリスト変換仕様

## 参照ブックの分析結果

`integration/pickup-list.xlsx`の「手順」シートと4つの作業シートを分析した。作業は次の処理に置き換えられる。

1. 2店舗の在庫CSVを読み込む。
2. SafeSizeエラーリストの`EAN`と在庫CSVの`スキャンコード`が一致する行を、在庫CSVの順序のまま抽出する。
3. 在庫CSVの13列から提出対象の11列を選択する。
4. `自社品番`が重複する場合、在庫CSVで最初に現れた1行だけを残す。
5. `server/data/pickup-list-template.xlsx`と同一構成の提出用Excelを生成する。

参照ブックでは、在庫19,522行とエラーリスト4,618行から263行が一致し、`自社品番`の重複232行を
削除した結果は31行だった。この規則で「step1_結合データ」と
「step2_結合データ商品重複削除(ピックアップリスト)」の全行・全列を完全に再現できることを確認した。

## 入力

### SafeSizeエラーリスト

画面全体へのドラッグ&ドロップまたはファイル選択で`.xlsx`ファイルを1件指定し、確定ボタンで
アップロードする。各シートの先頭100行から、次のいずれかのヘッダー行を自動検出する。
シート名とヘッダー行番号は固定せず、空行は読み飛ばす。

- 1列形式: 値がある列が1列だけなら、ヘッダー名と列位置は任意。
  最初の空でない行をヘッダーとして除外し、その下をEANデータとして読み込む。書式だけの空セルは列に数えない。
- 複数列形式: `EAN`、`JAN`、`JANコード`、`スキャンコード`、`スキャンコード(jan)`の
  いずれかのヘッダー名から照合列を特定する。列順・列数・他の列のヘッダー名は問わない。
  英字の大小、全角・半角、前後の空白は正規化する。
- 同じヘッダー行に候補列が複数ある場合（例: `EAN`と`JAN`の両方）はエラーにする。
  照合したい列だけに上記のヘッダー名を付ける。

従来のSafeSizeエラーリストやシューズマスターも同じ規則で読み込む。
ヘッダーを維持すれば、EAN列を移動したりEC-IDなどの列を追加・削除したりしても受け付ける。
複数シートの場合、認識した最初のEAN/JAN入力シート（またはデータのある1列シート）を使う。
それらがなければ、最初に見つかったスキャンコード列を使う。
これにより、在庫・作業シートが先にある既存ブックでも入力リストを優先し、複数シートを重複集計しない。

照合には`EAN`だけを使用する。ファイル上限は20MBとする。

### 店舗在庫CSV

最新の店舗在庫CSVをサーバーが自動取得する。対象店舗は`10309`と`10319`に固定し、それ以外の店舗行は
処理しない。取得結果はサーバープロセス内で1時間キャッシュする。

列順は次の13列とする。

```text
スキャンコード, 部門コード, 部門名, ３桁, 自社メーカー品番, ブランド名, 商品名,
品種名, 品目名, 自社品番, サイズ名, 店舗コード, 店舗名
```

## 照合と重複削除

- `EAN`と`スキャンコード`は文字列へ正規化し、13桁未満は左側を`0`で埋めて完全一致で照合する。
- 抽出順は店舗在庫CSVの行順を維持する。
- サイズ単位・店舗単位で同じ商品が複数行一致しても、`自社品番`ごとに最初の1行だけを出力する。
- したがって、同じ自社品番が両店舗に存在する場合も、在庫CSVで先に現れた店舗の行が残る。
- 一致商品が0件の場合は空ファイルを作らず、利用者へエラーを返す。

## 提出用Excel

`server/data/pickup-list-template.xlsx`をテンプレートとして読み込み、シート名、列順、列幅、行高、罫線、フォント、
表示形式、固定行、フィルター、条件付き書式、数式を維持する。ワークブックは次の2シートで構成する。

### 集計表

`シューズスキャン業務進捗`の集計表と数式をそのまま維持する。総数と残数のキャッシュ値だけは、
今回出力する商品件数へ更新する。

### ピックアップ

2行目に次の18列を持つ。

```text
コメント, ピックアップ, スキャン, データ登録, 返却, 完了済, No.,
部門, 部門名, 3桁, メーカー品番, ブランド, 商品名, 品種名, 品目名, 自社品番, 店舗, 店舗名
```

- A〜E列は作業日とコメントを記入する進捗管理列として空欄のまま出力する。
- F列はB〜E列がすべて入力されたとき`完了`を表示するテンプレート数式を維持する。
- G列は1から始まる連番を出力する。
- H〜R列へ、重複削除後の11列を3行目から出力する。
- 2行目の固定、`A2:R814`のフィルター、自社品番列の重複条件付き書式を維持する。
- テンプレートが用意するデータ行は3〜814行の812件であり、これを上限とする。

| H〜Rの出力列 | 在庫CSV列        |
| ------------ | ---------------- |
| 部門         | 部門コード       |
| 部門名       | 部門名           |
| 3桁          | ３桁             |
| メーカー品番 | 自社メーカー品番 |
| ブランド     | ブランド名       |
| 商品名       | 商品名           |
| 品種名       | 品種名           |
| 品目名       | 品目名           |
| 自社品番     | 自社品番         |
| 店舗         | 店舗コード       |
| 店舗名       | 店舗名           |

部門、3桁、自社品番、店舗などのコード値は、先頭ゼロを維持するため文字列セルで出力する。

確定後の画面には、上記18列をExcelと同じ列順で表示する。画面表示用データとダウンロード用Excelは
同じ変換結果から同時に生成し、表示内容とダウンロード内容を一致させる。別のファイルを選択した場合は
確定結果を破棄し、再度の確定が完了するまで画面表示とExcelダウンロードを無効にする。

## エラー条件

- `.xlsx`以外、空ファイル、20MB超過
- 複数列形式でEAN・JANなどの対応ヘッダーが見つからない、または候補列が複数ある
- `EAN`のデータ行がない、または数字以外の値がある
- 店舗在庫CSVの列数・ヘッダー順が不正
- 店舗在庫CSVに対象店舗行がない
- 一致する商品がない
- 重複削除後の商品が812件を超える

アップロードファイルと生成ファイルはメモリ上だけで処理し、永続化しない。

## 強化品番ピックアップ

`/kyoka-pickup-list`は自社品番専用の画面。通常ピックアップのEAN照合とは入力キーが異なる。
アップロードされた自社品番リストを強化品番の対象リストとして扱い、店舗在庫CSVへ直接照合する。
強化品番の商品CSVや商品一覧CSVは取得せず、ETLの固定3品番や期による制限も適用しない。

### 入力と列の特定

- Excel（`.xlsx`）1件、20MBまで。各シートの先頭100行でヘッダーを探す。
- 1列形式: ヘッダー名・列位置は任意。最初の空でない行をヘッダーとして除外する。
  データは常に自社品番として扱い、EANとは照合しない。
- 複数列形式: `自社品番`または`Retailer internal code`のヘッダー名から対象列を特定する。
  列順や追加列は自由。大文字小文字、全角半角、前後の空白を正規化する。
- EAN/JANなどの列が併存しても読み込まない。自社品番の候補列が複数あればエラーにする。
- 空シート・空行は飛ばす。最初に認識した入力シートだけを使い、複数シートを合算しない。
- 自社品番は数字として検証し、文字列のまま保持する。数値セル・全角数字・整数の`.0`表記に対応する。
  EAN用の13桁ゼロ埋めは行わず、文字列セルの先頭ゼロは保持する。
- 入力件数は空行を除いた自社品番の行数。重複した入力品番で在庫を二重計上しない。

### 照合と出力

- 店舗在庫CSVの`自社品番`と、アップロードした自社品番を完全一致で照合する。
- 店舗は`10309`・`10319`。サイズが異なるJANも同じ自社品番なら照合対象にする。
- 在庫CSVの順序を維持し、自社品番ごとに最初の1件を残す。
- 在庫CSVのサーバーキャッシュは1時間。強化品番CSVへのS3権限や`SHOE_KYOKA_DATA_KEY`設定は不要。
- 出力は通常ピックアップと同じ18列の提出用テンプレート（集計表・ピックアップ）。最大812品番。
  EC-ID・EC-URLはこの提出用テンプレートには追加しない。
- ファイル名は`kyoka_pickup_list_YYYYMMDD.xlsx`（日本時間）。表示とダウンロードは同じ生成結果を使う。
- `POST /api/kyoka-pickup-list`は表示・Excelデータ、`POST /api/kyoka-pickup-list.xlsx`はExcelを返す。
  ログインと`file`のアップロードが必須。JSONの更新日時は店舗在庫の`inventoryLastModified`のみ。
- 通常画面と強化品番画面の選択ファイル・結果は別々に保持する。ファイル変更時はその画面の結果を破棄し、
  再確定までダウンロードを無効にする。
- 在庫一致0件、CSV検証エラー、812件超過は原因を表示し、Excelを生成しない。

今回の自社品番方式への切り替えにはSDOアプリのデプロイが必要。ETLへの強化品番SQLの追加・更新は不要。
