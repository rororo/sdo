# 強化品番商品一覧

`/kyoka-products`で自社品番リストをアップロードし、現在の商品一覧と同じ対象期の商品を絞り込む。
対象品番のJAN・サイズ別の行をすべて表示・出力する。店舗在庫の照合や自社品番ごとの1行集約は行わない。

## 入力

- `.xlsx`を1件、20MBまで。選択または画面へのドロップ後、「アップロードを確定」で処理する。
- 強化品番ピックアップと同じ自社品番パーサーを使用する。
- 1列形式はヘッダー名・列位置が任意。複数列は`自社品番`または`Retailer internal code`から列を特定する。
- ヘッダーは先頭100行から探す。最初に認識したシートを使用し、空行は読み飛ばす。
- 全角数字・前後の空白・整数の`.0`表記を正規化する。EAN用のゼロ埋めは行わない。
- 複数列のEANや他の列は照合に使わない。自社品番候補列が複数ある場合や数字以外の品番はエラー。

## 抽出と表示

- 通常の商品一覧と同じ商品リポジトリ、対象期のS3キー、1時間キャッシュを使用する。
- 商品CSVの自社品番とアップロードした品番を完全一致で照合する。
- 重複入力品番は抽出条件として1件扱い。元の商品CSVの行順を維持し、各JAN・サイズ行を保持する。
- 通常商品一覧と共通の15列テーブルで、50行ずつ表示する。EC-ID・EC-URLも含める。
- 入力行数、入力品番数（重複除去後）、一致品番数、商品行数、対象期、商品データ更新日時を表示する。
- 未一致品番を折りたたみで確認できる。未一致は「対象期の商品CSVに存在しない」という意味であり、
  全期間の商品マスターに存在しないことを意味しない。
- 全件未一致は0件として表示する。Excelダウンロードは無効にする。
- 通常の商品一覧・2種類のピックアップとは選択ファイルと抽出結果を別々に保持する。
- ファイル変更・選択解除で結果を破棄する。処理中の変更は古いリクエストを中止し、遅い応答で結果を上書きしない。

## Excel

- 既存の商品マスター生成処理で、絞り込み結果の全ページ分を登録用23列に変換する。
- EC-ID・EC-URLはV列・W列。分類マスターにない商品の属性は既存仕様どおり空欄にする。
- ファイル名は`kyoka_shoe_master_<対象期>.xlsx`。対象期を持たないテスト用キーでは`current`を使用する。
- ピックアップテンプレートの812品番制限は適用しない。

## APIとデータ整合性

ログイン必須。いずれも`multipart/form-data`の`file`に入力Excelを送信する。

- `POST /api/kyoka-products`: 最初の確定。`page`は1が既定。結果と`version`を返す。
- `POST /api/kyoka-products?page=N&version=...`: 同じファイルでページを移動する。
- `POST /api/kyoka-products.xlsx?version=...`: 同じファイルで全件をExcel出力する。

2ページ目以降とExcel出力には`version`を必須とする。参照データの保存先・更新情報・商品内容と
入力品番からバージョンを計算する。取得時刻そのものには依存しないため、内容が同じなら別ECSタスクでも継続できる。
サーバーが参照した商品データ・対象期・入力条件が確定時と異なる場合は409を返し、再確定を促す。
ソースのS3更新検出は既存の1時間キャッシュに従う。

アップロードファイル・抽出結果をサーバーに永続保存しない。画面のリロード後は再アップロードが必要。
取得失敗時も古い結果を破棄し、入力ファイルを保持して再確定できるようにする。

## 検証とデプロイ

- APIテスト: 重複、部分一致、全件未一致、50行超のページ分割、全件Excel、EC項目、入力エラー、
  データ・期・入力の変更、複数アプリインスタンス、813品番出力を検証する。
- E2E: 提供された9月の29品番Excelと固定商品データを使用する。本番在庫やAWS接続には依存しない。
- 通常の商品テーブルを共通化し、既存3画面も回帰確認する。
- SDOのアプリ更新のみ。ScanalyticsのSQL変更・データ再投入・新規S3権限は不要。
